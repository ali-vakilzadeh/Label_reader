Apparel Vision & Intake Suite: System Architecture & Workflow Report
1. System Overview & Purpose
The Apparel Vision application is an enterprise-grade mobile intake, classification, and cataloging tool for apparel, footwear, and fashion accessories. It replaces slow, error-prone manual inventory entry with an intelligent pipeline combining on-device ML Kit barcode detection, multi-angle camera capture, asynchronous Gemini Vision AI extraction, human-in-the-loop review, duplicate item cloning, and an offline-first Room SQLite daily ledger.
2. Core Workflows & Step-by-Step Journeys
Workflow A: New Item Intake (Two-Phase Capture)
Phase 1 – Barcode Lock (apparel_id):
Real-Time ML Kit Scanning: As soon as the camera opens, Google ML Kit analyzes live viewfinder frames. An aiming reticle with an animated laser guide assists targeting.
Supported Formats: EAN-13, UPC-A, QR Code, Code-128, Code-39, etc.
Feedback: A haptic pulse and visual pill lock the detected barcode (e.g. BAR-849204).
Manual / Fallback Options: Operators can type barcodes manually or tap "Gen Demo ID" in Demo Mode.
Phase 2 – Multi-Angle Photo Capture:
Batch Photo Capture: The operator captures 1 to 8 high-resolution photos of brand tags, care instructions, fabric labels, and overall product views (IMG_<apparel_id>_<index>.jpg).
Thumbnail Strip & Re-Scan: A horizontal gallery lets the operator review or delete individual photos before finalizing.
Batch Enqueue: Tapping "Finish Item" bundles the photos with the barcode and stores the scan batch in Room SQLite (STATUS_PENDING_VISION).
Workflow B: AI Vision Extraction & Queue Management
Background AI Processing:
Automated / Manual Triggers: When Auto-Sync AI is active, scans are automatically transmitted. Alternatively, operators can trigger batch processing from the Review screen.
Secure Multipart Transmission: The app streams the captured images and metadata via Retrofit (multipart/form-data) to the companion Node.js Express middleware server.
Cloud Gemini Vision Analysis: The server routes image inputs to Gemini multimodal models using structured JSON schema extraction.
Extracted Fields & Normalization:
Category & Sub-Category: Standardized taxonomy (e.g., clothing, shoe, accessories mapped to specific garments).
Gender & Season: male, female, unisex, kids / spring/summer, fall/winter, all-season.
Brand, Origin & Sizing: International brand detection, country of origin, normalized sizes (S, M, L, 32W x 34L, US 10.5).
Color, Material & Pricing: Primary color, fabric composition (e.g., 100% Merino Wool), currency-formatted MSRP.
Physical Weight & Metrics: Net and Gross garment weight (e.g., netto and brutto).

Workflow C: Operator Quality Assurance & Ledger Verification
Interactive Review Screen:
Scans are categorized into Pending Extraction, Extracted (Awaiting Review), and Verified (Completed).
Human-in-the-Loop Inspector:
Tapping an extracted item opens an interactive inspection dialog.
Confidence-Coded Inputs: High-confidence fields appear in green/neutral; low-confidence extractions appear in amber with warning badges.
Photo Reference Carousel: Operators can swipe through the original high-resolution tag photos while editing values.
Confirmation: Tapping "Approve & Add to Ledger" moves the record to DailyLedgerEntity.
Workflow D: Fast Item Duplication (Parent-Child Cloning)
Use Case: Ingesting multiple identical garments that share identical tags/attributes but have distinct individual barcodes.
Workflow:
From the Daily Ledger or Review screen, tap the Duplicate (Copy) button.
The operator scans or types the new barcode (apparel_id).
The system creates a child record instantly copying all extracted attributes, without re-running AI vision.
The child record is tagged with parent_item_id = <original_barcode> and displays a "Child of #<parent_id>" badge.
Workflow E: Offline Mode, Demo Mode & Connectivity Safeguards
Demo Mode (On / Off):
Demo Mode OFF: If the device is offline or the server fails, all captures are safely cached locally in Room SQLite and remain pending until connectivity is validated.
Demo Mode ON: If the server is unreachable, the app falls back to local heuristic extraction for testing/demonstrations.
Isolated Demo Record Tagging:
Any record processed in Demo Mode is automatically assigned sequential demo identifiers (demo_0001, demo_0002, ...).
In both the Review list and Daily Ledger, demo items are tagged with an amber DEMO badge.
In CSV exports, a dedicated record_type column clearly distinguishes DEMO from REAL records.
First-Run Connection Floating Banner:
On startup, if the server is unreachable and Demo Mode is not configured, a floating notification alerts the user:
"server setting failed, set server connection or activate demo mode"
Quick action buttons allow navigation to Server Settings or immediate Demo Mode activation.
Workflow F: Data Export & Storage
Daily Active View vs. Historical Records:
Operators can clear the daily active screen at the end of a shift without losing data.
A history view allows operators to inspect or restore historical SQLite records.
CSV Ledger Sharing:

Key Rules of Image Assignment:
Deterministic File Naming:
When photos are captured in CaptureScreen.kt, they are written directly to the app's secure internal storage directory (context.filesDir/scans/):
Atomic Semicolon Delimitation:
Multiple image paths for a single item are combined into a single string:
Multimodal Batch Ingestion:
When transmitting to the AI server, all image files in the list are attached as separate images multipart parts. Gemini Vision evaluates all images together in a single prompt context, allowing it to correlate information across different tags (e.g., brand from Image 1, material from Image 2, and price from Image 3).
Cloned / Duplicate Items:
When an item is duplicated using the Parent-Child Cloning workflow, the child record inherits the exact same image_files path string from the parent, saving storage space while keeping visual references intact.

Endpoint 2: Multimodal Apparel Vision Extraction
Route: POST /api/extract/apparel
Headers: Authorization: Bearer <jwt_token>
Request Format (multipart/form-data):
apparel_id: String (e.g. BAR-849204)
username: String (e.g. operator_01)
images: File array (image/jpeg binary parts, 1 to 8 files)
Middleware Execution Flow:
Receives and buffers multipart image streams using multer.
Converts image buffers to Gemini inline base64 image parts.
Sends images to Gemini Vision with a strict system prompt instructing structured extraction.
Returns the standardized JSON payload back to the Android client.
